# Таня и голодный кот

Одна мобильная сцена auto-runner на Phaser 3 + TypeScript + Vite, без backend, внешнего арта и сохранений. Таня бежит сама; игрок управляет только прыжками. Цель забега — 3–5 минут, события идут примерно каждые 1–2 секунды на обычной скорости. Дизайн задаёт `GAME_DESIGN.md`.

Нужен Node.js 22.12+ (или 20.19+).

```sh
npm ci
npm run dev
```

Открой адрес Vite. Для телефона в одной сети используй сетевой адрес компьютера и порт 5173. Играй горизонтально.

```sh
npm run build
npm run preview
```

Production-файлы — в `dist/`. Размещай **всю папку** на статическом HTTPS-хостинге. Manifest, PNG-иконки и service worker включены в сборку. Относительные пути поддерживают размещение в подпапке, например на GitHub Pages.

## Установка на телефон

1. Опубликуй `dist/` и открой HTTPS-ссылку на телефоне. Адрес компьютера вида `http://192.168…` подходит для разработки, но не для полноценного PWA с офлайн-режимом.
2. Android: открой в Chrome и нажми «Установить» в игре, либо меню ⋮ → «Установить приложение» / «Добавить на главный экран».
3. iPhone: открой в Safari → «Поделиться» → «На экран Домой» → «Добавить». Системное окно установки на iOS нельзя открыть программно: кнопка игры показывает эти шаги.
4. Запускай с иконки. Играй горизонтально; iOS может потребовать повернуть телефон вручную.

Для первой загрузки нужен интернет. В окне «Установить» дождись сообщения «Игра сохранена», затем можно проверить запуск в авиарежиме. Сохранения прогресса по-прежнему нет: каждый новый запуск начинает сцену заново. При новой публикации закрой все окна установленной игры и открой снова, чтобы применить обновление; текущий забег не перезагружается автоматически.

Варианты публикации:

| Вариант | Как разместить |
| --- | --- |
| Netlify — проще всего для первой проверки | Собери `npm run build`, загрузи папку `dist` через ручной deploy в Netlify. Получишь HTTPS-ссылку. |
| Vercel — автоматические обновления из GitHub | Подключи репозиторий, build command `npm run build`, output directory `dist`. |
| GitHub Pages — всё рядом с репозиторием | Публикуй содержимое `dist` через GitHub Actions; в настройках Pages выбери источник GitHub Actions. |

Сборка создаёт `dist/sw.js` со списком всех файлов и версией кеша. В `npm run dev` service worker не включается. Для локальной проверки PWA используй `npm run build` и `npm run preview` на localhost; для телефона нужна HTTPS-ссылка. Хостинг и HTTPS-ссылка ещё не настроены.

### GitHub Pages для этого репозитория

Workflow `.github/workflows/pages.yml` собирает игру при каждом push в `main` и публикует `dist/` через GitHub Actions.

1. В репозитории открой **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Открой **Actions → Publish game to GitHub Pages → Run workflow**, выбери `main` и запусти. Последующие изменения в `main` публикуются автоматически.
3. После успешного job `deploy` ссылка на сайт будет в **Settings → Pages** и в deployment `github-pages`.

Workflow сначала проверяет, включён ли Pages и выбран ли источник GitHub Actions. Ошибка **Verify GitHub Pages is enabled** означает, что сайт недоступен токену workflow: проверь включение Pages и ограничения тарифа для приватных репозиториев. Ошибка **Verify Pages uses GitHub Actions** означает, что выбран другой источник публикации. После исправления настроек перезапусти workflow. Автоматическое включение Pages требует административного токена; он не добавляется в проект.

Ожидаемый адрес для этого репозитория: `https://pavelmartynovlive-bit.github.io/something-app/`. Он станет доступен только после успешной публикации. Если Pages недоступен для приватного репозитория на текущем тарифе, GitHub покажет ограничение в Settings → Pages; не меняй видимость репозитория без отдельного решения.

## Управление и механика

- Таня автоматически бежит вправо со скоростью 330px/s. На телефоне тапни в любом месте игровой области; на компьютере Space / ↑ — прыжок.
- Прыжок не требует отдельной энергии. Coyote time — 130ms, jump buffer — 150ms.
- Во время забега энергия постоянно расходуется (3,5/с). Столкновения с платформами/бабками снимают ещё 15; общий cooldown 1,4 секунды защищает от повторного удара.
- Самокаты едут навстречу: удар отнимает 12 энергии и замедляет на 650ms.
- Голуби вспархивают при приближении. Прыгни через стаю; контакт снимает 6 энергии и слегка трясёт камеру.
- Lipton даёт +22 энергии сразу, без остановки (максимум 100).
- Лавочки опциональны (одна на квартал): если энергия ниже 65, касание на земле включает отдых на 2,5 секунды (+22 энергии/с). Таня садится и затем продолжает бежать. Можно перепрыгнуть лавочку; при большем запасе энергии она пробегает мимо. Каждая лавочка используется один раз за забег.
- При нуле энергии скорость падает до 130px/s, прыжок становится ниже. Энергия сама не восстанавливается — нужен Lipton или лавочка. На нижнем маршруте нет ям.
- На карте 80 пакетиков корма: 20 над наземными препятствиями и 60 на верхних ветках. Счётчик показывает фактическое количество — «Корм 0/80».
- Кот принимает минимум 3 пакетика. При меньшем количестве появляется «Нужно ещё немного корма» и кнопка повторного забега; победа не засчитывается.
- Падение возвращает на безопасный checkpoint. Собранный корм и Lipton не появляются повторно. Повторный забег сбрасывает все предметы и счётчики.

Все параметры и раскладка уровня — в `src/settings.ts`. Сцена — `src/main.ts`, обработка тапа — `src/controls.ts`.

## Плотный уровень и выбор маршрута

Один непрерывный уровень длиной 60000px: десять авторских последовательностей примерно по 18 секунд обычного движения. Вступление знакомит с препятствием и кормом, затем с голубями, подъёмом и самокатом. Далее чередуются четыре типа верхней геометрии: обычная лесенка, низкий длинный путь, перепады вверх-вниз и разделённые верхние опоры. Во второй части чаще комбинируются знакомые движущиеся опасности и выбор высоты; новые механики не вводятся. Раскладка детерминирована, случайной генерации нет.

Основные события разделены примерно 330–650px (1–2 секунды обычного движения). Корм направляет прыжки над препятствиями и отмечает подъёмы. В каждом квартале два верхних маршрута с кормом/Lipton и одна лавочка снизу. Верхняя ветка приносит больше корма и позволяет восстановиться без остановки, нижняя даёт возможность полноценного отдыха. Между сериями остаётся небольшая передышка, а после спусков — самокаты.

Под верхними ветками непрерывная земля. Промах не вызывает смерть или возврат на checkpoint. Опоры шириной 240–420px, подъёмы до 60px, промежутки 40–60px; боковые грани не блокируют автобег. Платформы утолщены с 18 до 28px, масштаб увеличен примерно на 10%; стиль placeholder-графики сохранён. Вертикальное смещение камеры ограничено 40px, чтобы нижняя дорожка оставалась видимой. Физика прыжка, coyote time и jump buffer сохранены.

Энергия расходуется быстрее, а Lipton восполняет 22 вместо 30. Во время длинного забега нельзя рассчитывать на постоянно полный запас: можно выбирать восстановление на верхней ветке или потратить 2,5 секунды на отдых снизу. При нуле энергии движение вправо остаётся возможным по безопасной земле.

## Что проверено

Production-сборка и TypeScript проходят. Через Playwright в Chromium выполнены полные забеги с клавиатурными событиями и игровой физикой: преимущественно нижний путь (3:29, 28 пакетиков, 9 остановок на отдых), выбор верхних веток с восстановлением по необходимости (3:17, 68 пакетиков, 2 остановки), намеренно пропущенный первый подъём с продолжением снизу (3:29, 59 пакетиков). Во всех случаях кот накормлен, возвратов на checkpoint и блокировок геометрией нет.

Каждая из 20 верхних веток отдельно пройдена при полном запасе энергии: проверено приземление на все 95 платформ с обычной физикой прыжка. Дополнительно пройдены весь уровень без прыжков и весь уровень с нулевой начальной энергией: Таня восстанавливается на существующих объектах и доходит до кота без soft-lock. При отсутствии прыжков корм не собирается и победа не засчитывается; такой забег занимает около 6 минут из-за частых столкновений и усталости, дольше целевого активного прохождения.

Проверены прыжок реальным мобильным тапом, coyote jump с края ящика на козырёк и jump buffer перед приземлением. Максимальное изменение вертикальной камеры в полных забегах — менее 1 игрового пикселя за кадр. Мобильный вид проверен в Chromium с viewport 844×390. Эти проверки подтверждают достижимость и правила; ощущение ритма стоит оценить на телефоне.

Для PWA проверены manifest и отсутствие ошибок устанавливаемости в обычном профиле Chromium, кеширование всех файлов сборки, перезагрузка и игра с отключённой сетью, работа из корня сайта и подпапки `/tanya/`. Инструкция для iPhone проверена с его user agent, а установка на настоящем iPhone/Android ещё не проверена.

## Ручная проверка на телефоне

Проверь прыжки тапом в разных местах игровой области, поворот экрана, возврат из другой вкладки, отсутствие скролла и zoom, безопасное падение с верхней ветки, слабый прыжок при нуле энергии, оба способа восстановления, пропуск лавочки, сбор корма и оба финальных исхода. Настоящие Safari/iOS и Chrome/Android требуют проверки на устройствах.
