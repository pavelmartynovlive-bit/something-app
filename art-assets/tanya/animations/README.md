# Tanya animation sheet

GPT Image animation artwork based on the current approved loose-hair Tanya.
1536×1024 transparent PNG; 4 columns × 5 rows, 20 isolated right-facing poses.

| Row | Frames |
| --- | --- |
| 1 | idle 1–4 |
| 2 | run 1–4 |
| 3 | run 5–8 |
| 4 | jump-start 1–2, jump 1–2 |
| 5 | fall 1–2, landing 1–2 |

Use explicit `tanya-animation-atlas.json` frame rectangles rather than fractional
grid slicing: 1024 is not divisible by five. `tanya-animation-states.json` contains
frame order and provisional preview rates. Each pose has at least five pixels of
clearance from its cell boundary at alpha128; no opaque frame overlaps a cell edge.
The original generated PNG is copied unchanged; metadata does not repaint it.

Open `preview.html` beside its PNG for state playback, pause and single-frame review.
Atlas metadata registers every pose on a common192×192 virtual canvas with a
provisional bottom-center anchor(96,172). This is a starting registration, not an
anatomically verified rig. Hand-drawn/generated frames require in-engine review
of loop continuity, especially alternating run legs, and minor proportion/anchor
drift before claiming a finished production animation. Idle motion is very subtle.

No game runtime, physics, movement, level, current production character, or
GitHub Pages deployment is changed by this asset deliverable.

## Runtime integration

The source delivery above is now integrated by `src/tanya-visual.ts`. The approved
PNG is copied unchanged into `public/assets/characters/tanya/animations`; runtime
registrations and final FPS are generated by `scripts/prepare-tanya-animation.mjs`.
The standalone preview retains its provisional original registration/rates; use
the actual game and `docs/tanya/README.md` for final integration behavior/checks.
